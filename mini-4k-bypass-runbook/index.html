Mini 4K Bypass Runbook

The exact commands to decompile the DJI Fly APK and hunt for the drone-registry gate that's keeping the Mini 4K off the SDK's flight-control path.

Where things stand: the DJI Fly APK (~706 MB, pulled off the Fire tablet via ADB) is sitting on your phone. Chat upload has a hard size ceiling well under that — don't fight it again.

Next move: get the file onto the PC (Drive, email-to-self, or USB when you're at the desk), then run Phase 05 below through Claude Code. Everything before that is reference, in case you want to run any step by hand.

01

Land the APK on the PC

Any of these work — pick whichever's already open on your phone:

  • Upload to Google Drive / OneDrive from your phone, then download on the PC
  • Email it to yourself as an attachment (some providers cap attachments around 25 MB — if it bounces, use Drive instead)
  • Plug the phone into the PC over USB next time you're at the desk and copy it straight across

Drop it somewhere easy to type, e.g. C:\Users\18108\drone\dji_fly.apk.

02

Toolchain (reference — Claude Code can do this for you)

Two decompilers, used together: jadx turns the app's code back into readable-ish Java, apktool unpacks it into smali + raw resources (catches anything jadx chokes on). Both need Java.

PowerShell — Java + ripgrep
winget install EclipseAdoptium.Temurin.25.JDK
winget install BurntSushi.ripgrep.MSVC
PowerShell — jadx
mkdir C:\tools\jadx
curl -L -o C:\tools\jadx\jadx.zip https://github.com/skylot/jadx/releases/download/v1.5.6/jadx-1.5.6.zip
tar -xf C:\tools\jadx\jadx.zip -C C:\tools\jadx
PowerShell — apktool
mkdir C:\tools\apktool
curl -L -o C:\tools\apktool\apktool.bat https://raw.githubusercontent.com/iBotPeaches/Apktool/master/scripts/windows/apktool.bat
# then grab the current apktool-*.jar from https://bitbucket.org/iBotPeaches/apktool/downloads
# and save it into C:\tools\apktool as exactly "apktool.jar"

Add C:\tools\jadx\bin and C:\tools\apktool to your user PATH — same Environment Variables screen you already used for Claude Code, just two more entries in that same list.

Skip this by hand The version numbers above (jadx 1.5.6, whatever apktool build is current) will drift. Claude Code can check for the current release and fetch it itself — Phase 05's prompt tells it to install anything missing, so you don't have to keep this page's links fresh.
03

Decompile

Run both — jadx for readable code, apktool for the raw smali and resources jadx sometimes garbles:

PowerShell
jadx -d C:\Users\18108\drone\jadx_out C:\Users\18108\drone\dji_fly.apk
apktool d C:\Users\18108\drone\dji_fly.apk -o C:\Users\18108\drone\apktool_out

jadx alone can take several minutes on a 700 MB app — that's normal, let it run.

04

Hunt the registry

What we're looking for is DJI's internal drone/camera/product-ID table — and whichever check decides an SDK feature is or isn't available for a given ID. Search both output folders:

PowerShell — ripgrep
rg -il 'producttype|dronetype|cameratype' C:\Users\18108\drone\jadx_out
rg -il 'mini_4k|mini4k|MINI_4K' C:\Users\18108\drone\jadx_out C:\Users\18108\drone\apktool_out
rg -c 'MAVIC|MINI2|MINI3|AIR2S|M300' C:\Users\18108\drone\jadx_out --type java | sort -t: -k2 -rn | head -20

That third line is the useful trick: whichever file mentions the most known DJI product names in one place is almost certainly the registry/enum class itself — find that file, then check line-by-line whether the Mini 4K has its own entry.

Situation A — entry exists

Mini 4K shows up in the registry, just gated off from SDK flight control. Patch the gate, not the ID table — safer, and flight tuning stays accurate to the real drone.

Situation B — no entry

Mini 4K isn't represented at all. Falls back to spoofing as a supported drone (the Mini 2 → Mavic Air 2 precedent) — riskier, since flight parameters come from the impersonated model.

05

Hand it to Claude Code

The recommended path once the APK is on the PC. Open a terminal, run claude, and paste this in as one message:

registry (the classes that map a numeric ID to a drone model, historically

that decides whether SDK flight-control features are exposed for a given
product ID.

Please:
1. Check for Java, jadx, apktool, and ripgrep (rg) - install whatever's
   missing (winget is available).
2. Decompile the APK with both jadx and apktool into sibling folders next
   to the APK.
3. Search the output for classes/enums that look like a drone or camera
   product-ID table (cross-reference against known DJI model names: Mavic,
   Mini 2, Mini 3, Mini 3 Pro, Air 2S, Mini 4 Pro, M300, M350, Matrice,
   Inspire).

5. If it has an entry, find whatever code path gates SDK/flight-control

   Mini 4K would need to be let through.
6. If it's absent, identify which currently-supported drone has the
   closest flight characteristics (weight, prop size, max speed) to the
   Mini 4K, as the best spoofing target.
7. Write a findings report (file paths, class names, line numbers, and
   your recommendation) to C:\Users\18108\drone\findings.md so I can send
   it back to Claude for the next step.

When it's done, paste findings.md back to me here (or attach it — it'll be tiny) and we'll pick the exact Frida hook targets from there.
